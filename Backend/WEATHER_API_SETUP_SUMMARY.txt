HOW IT WORKS
============

User Request Flow:

1. User makes request to /pricing/calculate
2. Backend calls: snapshot = get_snapshot(user.work_zone)
3. Environmental Service:
   a. Sets timeout=5 seconds
   b. Makes async call to OpenWeatherMap API
   c. Makes async call to WAQI API (parallel)
   d. Waits for both to complete
   e. If both succeed: Parse + return real data
   f. If either fails: Log warning + return mock data
4. Backend passes environmental data to pricing engine
5. Pricing engine uses real factors:
   - Temperature → heat loading
   - Rainfall → rain loading
   - AQI → aqi loading
   - Wind → wind loading
6. Premium calculated with real environmental multipliers
7. Response sent with data_source="openweathermap+waqi" or "mock"
8. Frontend shows that premium is based on current conditions


FALLBACK BEHAVIOR
=================

The system has intelligent fallback logic:

✅ Both APIs working?
   → Use real data, data_source="openweathermap+waqi"

✅ OpenWeather fails, WAQI works?
   → Use mock data, data_source="mock"

✅ Both APIs fail?
   → Use mock data, data_source="mock"
   → Log warnings for debugging
   → User experience unaffected (mock is calibrated to be realistic)

✅ API keys missing?
   → Auto-switch to mock data, data_source="mock"
   → No errors, just graceful degradation
